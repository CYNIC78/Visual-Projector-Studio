# Visual Projector Studio / VP Studio

**VP Studio** — локальная мультимедийная студия для двухстороннего мультимодального взаимодействия пользователя с локальными большими языковыми и визуальными моделями.

Проект не является обычным веб-приложением и не является обычной игрой. Это рабочая среда, где:
- пользователь общается с LLM;
- LLM видит текстовый **и визуальный** контекст;
- LLM может управлять проектором через команды;
- LLM может пользоваться tools для поиска, памяти, навигации по сценам и подготовки генерации ассетов;
- пользователь и модель вместе создают визуальный словарь сцены/персонажа;
- сгенерированные ассеты попадают в умную галерею и затем используются в ролеплее.

**Коротко:** VP Studio — AI multimedia runtime studio для иммерсивного чата, визуального сторителлинга и генерации ассетов.

## Запуск

### Через лаунчер (рекомендуется)

1. Запустите `VP Studio.exe`
2. Выберите папку для кеша WebView2 (по умолчанию `R:\VP_Cache` для RAM-диска, или любую другую папку)
3. Нажмите **Launch VP Studio**

Лаунчер позволяет:
- Выбрать расположение кеша WebView2 (RAM-диск, SSD, HDD)
- Очистить кеш
- Открыть папку кеша
- Включить быстрый запуск (Quick launch next time)

### Прямой запуск (для разработки)

```
neutralino-win_x64.exe
```

## Модель хранения данных

**Ничего не пишется на диск автоматически.** Все изменения живут в памяти до явного сохранения.

- Кнопка **💾 Save** в топбаре сохраняет все изменения
- Индикатор показывает статус: «Сохранено» / «Не сохранено»
- Горячая клавиша: `Ctrl+S`

Это даёт:
- Полный контроль над persistence
- Безопасное тестирование без риска испортить данные
- Возможность отменить изменения простым закрытием без сохранения

## Ключевые возможности

### 1. Проектор и Focus Mode

Проектор — экран сцены. Модель ставит на него кадр командой `[IMG:tag]`, пользователь — кликом в галерее.

**Focus Mode** превращает статичную картинку в управляемую камеру: зум, панорамирование, 2.5D-параллакс через WebGL (depth-слой), фокал-лок по клику. Настройки камеры запоминаются в метаданных ассета, так что каждый кадр «помнит» свой ракурс. Модель тоже может вести камеру — через `[FOCUS:...]`.

### 2. Умная галерея (Smart Gallery)

Галерея — источник истины для визуальных ассетов. Ассет вызывается по тегу: `emily_smile`, `emily_angry`, `room_night`.

Ассеты живут в иерархии **категория → таб → ассеты**. Категория — это пак (например, `Characters`, `Locations`), таб — комната сцены (`emily`, `Forest`).

Галерейный тег используется:
- проектором;
- моделью;
- reference-ссылками Prompt Node;
- визуальной витриной (Gallery View).

### 3. Gallery View — модель видит галерею глазами

Ключевая механика последних билдов. Содержимое активного таба собирается в **коллаж-витрину** — одну картинку с превью-карточками и подписями `[IMG:tag]`. Эта картинка уходит модели как визуальное вложение.

Модель не гадает по списку тегов, что за ассеты у неё есть, — она их **видит** и выбирает кадр глазами.

### 4. Сцены как комнаты (FSM галереи)

Табы и категории — это конечный автомат с тремя состояниями, видимыми в сайдбаре цветными точками:

| Точка | Состояние | Смысл |
| --- | --- | --- |
| 🟢 | `open` | **Активная сцена** — комната, где прямо сейчас происходит действие. Её содержимое на витрине и перед глазами модели. |
| 🟡 | `collapsed` | **Кандидат меню** — модель видит только имя и описание, может войти командой. |
| 🔴 | `locked` | **Скрыто от модели** — рабочий верстак пользователя. |

Правила, на которых стоит система:

- **Ровно одна зелёная сцена.** Вход в новый таб автоматически закрывает предыдущий — «соло-переход».
- **Витрина — следствие сцены.** Метка Gallery View не отдельная кнопка: она есть тогда и только тогда, когда таб зелёный.
- **Категория активной сцены всегда открыта.** Зелёный таб не может прятаться в свёрнутом паке — иначе модель видела бы сцену, до которой не может донавигироваться.
- **Красный — только осознанно**, через контекстное меню. Точка переключает лишь зелёный ↔ жёлтый.
- **Клик по имени таба = менеджмент** (управление ассетами в гриде), **клик по точке = рантайм** (смена сцены). Два разных жеста, два разных смысла.

Строгость здесь намеренная: предсказуемый автомат гораздо важнее гибкости, особенно для слабых локальных моделей.

### 5. Public scene commands

Модель может писать команды прямо в ответ:

| Команда | Что делает |
| --- | --- |
| `[IMG:tag]` | Показать ассет в проекторе |
| `[IMG:tag:transition]` | Показать ассет с переходом |
| `[FX:name]` | Запустить визуальный эффект (можно `[FX:name:intensity]`) |
| `[FOCUS:position:zoom]` | Вести камеру: `[FOCUS:bottom:zoom]`, `[FOCUS:cinematic]`, `[FOCUS:reset]` |
| `[TAB:open:name]` | Войти в сцену — соло-переход, остальные табы закрываются |
| `[CAT:open:name]` | Раскрыть пак сцен |
| `[CAT:close:name]` | Убрать пак, когда история ушла дальше |
| `[ACTIVITY_REQUEST]`, `[ACTIVITY_START]` | Команды activity/game layer |

Эти команды публичны, видимы, replay-able и являются частью сцены.

Парсер (`VPTags`) прощает модели неточность: Unicode-нормализация, алиасы, нечёткое совпадение имён по расстоянию Левенштейна с консервативным порогом.

### 6. Tools

Tools — приватный structured-call слой модели:

| Tool | Назначение |
| --- | --- |
| `scene_navigate` | Перейти между сценами/паками **и увидеть результат** — возвращает свежую витрину картинкой |
| `gallery_search` | Найти ассеты по тегу или описанию |
| `asset_suggest` | Подобрать ассет под настроение/действие сцены |
| `scene_describe` | Сориентироваться: текущий кадр, говорящий, участники, сценарий |
| `recall_scene` | Поискать в истории чата то, что уже вытеснено из окна контекста |
| `timeline_check` | Темп сцены: счётчик сообщений, длительность, время с последней реплики |
| `character_note` | Профиль персонажа: описание, персона, состояние |
| `roll_dice` | Броски кубиков в RPG-нотации (`2d6+1`, `4d6k3`) — чтобы модель не выдумывала результат |
| `configure_prompt_studio` | Подготовить Prompt Node для batch-генерации ассетов |

Отдельно стоит `scene_navigate`: это не просто команда, а **замкнутый цикл** — модель совершает переход и тут же получает обратно новую витрину как изображение. Она буквально видит, куда пришла.

### 7. Asset Studio

Asset Studio — графовая студия генерации ассетов через `sd.cpp` CLI.

Текущий стабильный backend: **sd.cpp CLI**
`sd-server` считается экспериментальным и не блокирует развитие проекта.

## Asset Pack Factory

Одно из ключевых текущих направлений — Asset Pack Factory.

Пример сценария:
1. Пользователь загружает reference персонажа в галерею, например `emily`.
2. Пользователь обсуждает с LLM, какие ассеты нужны для ролеплея.
3. Модель планирует pack: эмоции, позы, состояния.
4. Пользователь утверждает план.
5. Модель вызывает `configure_prompt_studio`.
6. Tool создаёт Prompt Node tabs и reference links.
7. Пользователь открывает Asset Studio и жмёт `Produce All`.
8. Сгенерированные drafts попадают в нужный tab галереи.
9. Пользователь применяет drafts через `Apply All`.
10. Модель использует новые ассеты через `[IMG:tag]`.

**Правило v1:**
- 1 Prompt Node tab = 1 generated asset
- 1 configure_prompt_studio call = 1 thematic pack = 1 Gallery destination tab

Пример:
```
12 Prompt Node tabs
→ 12 generated emotion assets
→ Gallery / Characters / Emily Emotions
```

## Draft system

Generated ассеты из Asset Studio сначала попадают в галерею как drafts:
- `_draft: true`
- До Apply они живут в RAM runtime и не считаются persistent world assets.

После `Apply` / `Apply All` ассеты сохраняются в:
- `data/worlds/<world>/assets/files/`
- `data/worlds/<world>/assets/assets.json`

Это позволяет спокойно генерировать пачки, выбирать удачные результаты и выкидывать мусор.

## Архитектура

Код построен по схеме **«хозяин ↔ спутники»**: большой модуль-оркестратор регистрирует фасад на `window.VisualProjector`, а выделенные домены живут в отдельных файлах-спутниках. Связывает всё событийная шина `VP_HUB`.

Четыре хозяина:

| Домен | Хозяин | Спутники |
| --- | --- | --- |
| Движок проектора | `js/visual-projector.js` | `director-bus`, `vp-templates`, `projector-focus`, `vp-dialogs`, `vp-window-drag`, `projector-depth-renderer` |
| Галерея | `js/projector-gallery.js` | `gallery-hierarchy` (FSM табов), `gallery-collage` (витрина), `gallery-panel`, `gallery-depth` |
| Сессия / чат | `js/projector-session.js` | `session-manifests`, `session-panels`, `session-bus-panel` |
| Шелл и студия | `js/projector-shell.js`, `js/projector-asset-studio.js` | ноды в `js/nodes/`, воркеры в `js/workers/` |

Подробная карта — в `docs/module-map.md`.

## Принципы разработки

- Не ломать рабочую магию ради архитектурной красоты.
- Маленькие точечные патчи вместо большого rewrite.
- Явная persistence — ничего не сохраняется без команды пользователя.
- Галерея — source of truth для ассетов.
- Prompt Node хранит ссылки на gallery tags, не base64.
- Модель и пользователь должны иметь симметричные возможности там, где это полезно.
- Состояние, которое видит модель, не должно противоречить тому, что она видит на картинке.
- Предсказуемость важнее гибкости: строгий автомат лучше, чем гибкий, но непонятный.
- CLI backend считается стабильным; server backend — экспериментальным.
- Новые фичи рождаются из реального использования и тестирования.
