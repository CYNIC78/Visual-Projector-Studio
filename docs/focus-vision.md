# 🎯 Focus Mode — собрание рефлексии и дорожка идей

> Дизайн-документ (обсуждение, без правок кода). Дата: 2026-07-28, смена «творческая».
> Файл под рефлексией: `js/projector-focus.js` (1068 строк, спутник движка, v05+v10).
> Связанные: `js/director-bus.js` (FOCUS-команда, пресеты), `js/projector-games.js` (хост игровых модулей, 1441 строка — уже существует и ждёт механик).

---

## 1. Карта текущего режима

Три домена в одном модуле:

| Домен | Что есть | Ключевые точки |
|---|---|---|
| **Камера** | Вьюпорт `{x, y, zoom, focusZoom, step, dirty}`, lerp-глайд 0.12, wheel/drag/стрелки | `setProjectorViewport`, `ensureViewportGlideLoopActive`, `_targetViewport*` |
| **Глубина** | WebGL-параллакс, pivot (фокальная плоскость), strength, vignette, DoF, аберрация, клик-фокал-лок | `updateProjectorDepthLayer`, `performFocalLockAtClick` |
| **Мост внимания** | Snapshot Focus → кроп → манифест `[GAZE FOCUS ATTACHMENT]` (ttl:1) → модель видит глазами юзера | `captureFocusViewportDataUrl`, `session.queueManifest` |

Команда модели: `[FOCUS:position:zoom]` / `[FOCUS:zoom:x:y:pivot:vignette]` / пресеты (`FOCUS_PRESETS` в director-bus).
События в хабе уже есть: `projector:viewport-changed` (с `reason` — можно отличить юзера от модели).

Публичный API `window.VP_FOCUS` экспонирован целиком намеренно — «для будущих focus-фич и геймплея на фокальном внимании» (шапка модуля). Петля внимания уже замкнута:
**модель двигает камеру → юзер смотрит → юзер кликает/снимает → модель видит кроп → реагирует.**

## 2. Причесать (мелкие квирки, найдены при перечитывании)

| № | Квирк | Где | Статус |
|---|---|---|---|
| 1 | **Vignette-слайдер не ресинкается при смене ассета**: `applyProjectorViewportUI()` обновляет pivot+strength слайдеры, vignette — нет (только при создании HUD и в FOCUS-хендлере). Может показывать старое значение | projector-focus.js | ✅ кандидат на точечный фикс (~3 строки по образу соседних) |
| 2 | Мёртвый тернарник: `return vp.zoom > 1.001 ? 'both' : 'both';` | `getCurrentImageOverflowAxis` | косметика / задокументировать |
| 3 | Комментарий врёт: `nearThreshold: 0.8, // ...глубиной > 0.9...` | `updateProjectorDepthLayer` | косметика |

## 3. Идеи для ядра (рейтинг: дёшево → мощно)

### A. Событие `projector:focus-settled` — 3 строки, открывает всё
Глайд-луп уже умеет определять «долетели» (ветка `focus-drag-snap-final`), но наружу молчит.
Emit в хаб → примитив «камера встала»: модель шлёт `[FOCUS:top:zoom]`, ждёт settled, продолжает реплику. Режиссура пауз.
**Усилие: крошечное. Риск: нулевой (аддитивно).**

### B. Именованные якоря на ассете — ГЛАВНЫЙ МОСТ К FSM
`asset.focusAnchors: [{ name: "зеркало", x, y, zoom, pivot, vignette }]`, команда `[FOCUS:@зеркало]`.
Непрерывная камера → дискретный набор состояний = ноды автомата. Модель «гуляет по сцене» по именам.
UI: именование текущей позиции (долгий тап / кнопка в HUD). Хранение — в мете ассета (persist уже есть).
Побочный эффект: даёт достойную судьбу недостижимым пресетам (квирк №5).
**Усилие: среднее. Риск: низкий (аддитивно, своя ветка парсинга).**

### C. Тап как глагол взаимодействия
Сейчас клик без драга работает только при готовом WebGL (фокал-лок), иначе тихий `return`.
Эмитить `projector:screen-tap {rx, ry, uvX?, uvY?}` при ЛЮБОМ тапе → экран = указывалка независимо от depth.
«Тапни по кубку» — игры слышат.
**Усилие: малое. Риск: низкий.**

### D. Dwell-метр внимания
Раз в секунду сэмплить позицию вьюпорта в кольцевой буфер на State; модели — строчка контекста
«юзер 30 секунд разглядывает зеркало». Хоррор/детектив-золото.
**Усилие: ~20 строк. Риск: низкий (пассивный сэмплер).**

### E. Глаза по требованию для модели + zoom-gated секреты
Сейчас Snapshot Focus инициирует только юзер. Модельный вариант: `[FOCUS:@дверь:snap]` →
долетела (ждём settled из идеи A) → авто-кадр → кроп модели. Модель сама смотрит, куда хочет.
Отсюда шаг до киллер-механики: **секреты, видимые только при зуме** — записку на стене можно
прочитать, только приблизившись. Информационные ворота через камеру = бесплатный геймплей.
**Усилие: среднее (нужен A; пайплайн кропа уже есть в движке).**

### F. Камерные сценарии (shots)
`[FOCUS:seq:окно>зеркало>лицо]` с паузами — очередь глайд-целей с длительностями, emit на каждом шаге.
Модельные катсцены. Строить ПОСЛЕ якорей (B) — seq естественно собирается из имён.
**Усилие: среднее+. Риск: средний (асинхронный раннер — аккуратно с отменой при смене ассета).**

### G. Вишенка: миниигра-пример «найди спрятанное»
На готовом games-хосте (`projector-games.js`): FSM прячет объект в кадре, юзер ищет камерой,
фокал-лок/тап в целевом ректе ±ε → переход состояния → реплика модели через `requestAssistant`.
Ноль нового рендеринга, чистая обвязка событий A+C.
**Усилие: среднее. Зависит от: A, C (B желательно).**

---

## 4. Рекомендуемый порядок

**A → C → B → E → D → F**, затем G как праздник.
A+C = «входы» (внимание юзера наружу), B+E = «выходы» (режиссура модели), D — атмосфера, F — постановка.

## 5. НЕ трогаем (несущие конструкции)

- Глайд-lerp (настроен, хрупок, вся команда bus опирается на setGlideTarget)
- Кишочки WebGL depth-рендерера
- Unsafe-zone сессии (send-пайплайн/стриминг)

## 6. Факты, к которым приятно вернуться

- `emitProjectorViewportChanged(reason)` уже несёт `reason` — игры могут отличать камеру юзера от камеры модели БЕЗ новых правок.
- `VP_FOCUS.setGlideTarget/clearGlideTargets` уже публичны — внешний модуль (игра) может вести камеру напрямую, минуя парсинг тегов.
- `projector-games.js` уже умеет: `buildPromptContext`, activity-запросы с accept/decline, scene-event'ы в сессию, `requestAssistant`, hub-адаптер проектора (`set-current`, `get-state`). Механикам остаётся подписаться на события фокуса.
