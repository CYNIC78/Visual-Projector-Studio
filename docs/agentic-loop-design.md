# 🔁 Агентная петля vs спекулятивный лаг (дизайн, размышление)

Дата: 2026-07-29. Статус: **обсуждение, ждёт решения владельца** (код не тронут).
Триггер (владелец): «табы и категории — состояния FSM, которыми управляет
модель; FSM неточная, но бесплатная. Возвращаемся к дилемме: агентная
петля против лага на один шаг — модель открывает таб на текущем шаге, а
увидит контент только на следующем. Плата: время обработки вызова против
отсутствия реалтайм-фидбека (эффект спекуляции)».

---

## 1. Как устроено сейчас (факты)

- Ответ модели генерируется целиком (стримингом) на контексте хода N;
  команды (`[TAB:open:X]`, `[IMG:tag]`, `[FOCUS…]`) вытаскиваются из текста
  и исполняются шиной (очередь, delayMs) по ходу/после ответа.
- Исполнение меняет МИР (таб открыт, витрина пересобрана, манифест следующего
  хода богаче) — но ход N уже зафиксирован и ушёл юзеру.
- Грамматика честно **учит спекуляции**: шаблон манифеста прямо говорит
  «pulls assets into your NEXT turn». Лаг — задокументированная семантика.
- Следствие для FSM-игр: «вошла в комнату» и «описала комнату» — разные
  туры. Между ними — юзер. Рефлекторная игра («открыл → увидел деталь →
  среагировал») невозможна внутри одного тура.

## 2. Взвешивание

### 2.1 За статус-кво (лаг/спекуляция)
- **Цена ноль.** Один инференс на ход: никаких вторых вызовов, никакого
  роста токенов и времени — для локальных 7–12b это весомо.
- **Спекуляция тренирует планирование**: модель как ведущий готовит сцену
  на ход вперёд («шахматность» мышления); юзер получает ответ без пауз
  «модель осматривается…».
- Отсутствие новой машинерии: без tool-result сообщений, глубины петли,
  анти-loop брони.
- Ошибки FSM добирает юзер бесплатно (правит руками), или модель
  исправляется следующим туром — дёшево.

### 2.2 За агентную петлю
- **Чувства в реальном времени**: исполнить команду → получить наблюдение →
  продолжить В ТОМ ЖЕ туре. «Вошла в комнату — увидела — описала».
- Самокоррекция FSM: открыла не тот таб → увидела по наблюдению → исправила
  (close/open) без стыдобища перед юзером целым туром.
- Quality-тур для сценариев «посмотри и расскажи»: иначе модель описывает
  комнату по памяти/манифесту, а не по факту.
- Локальные модели умнеют — tool-loop протокол ближе к их обученным
  привычкам, чем планирование вслепую.

### 2.3 Честная цена петли
- Второй (третий) инференс на триггерных турах: время ответа ×2 в худшем
  случае; на локальных моделях — десятки секунд.
- Машинерия: tool-result синтез, индикатор «модель осматривается», глубина,
  анти-loop, журналирование двух assistant-сообщений, стриминг-UX.
- Переписывание грамматики шаблона: «NEXT turn» → «in this same turn»
  (две семантики под двумя флагами — наследие).

## 3. Варианты

**A. Статус-кво (лаг).** Ничего не трогаем; признаём шахматность фичей.
Для FSM-игр делаем отдельный костыль «авто-переход» позже, если будет больно.

**B. Микро-петля dir-only, глубина 1 (РЕКОМЕНДАЦИЯ).** Триггер — только
`[TAB:open/close]` / `[CAT:open/close]` (переходы сцен — единственное место,
где модели по-настоящему нужен фидбек сейчас). Исполнение → компактное
tool-result («[SCENE UPDATE] Вошла в «Tavern» (пак Places). Видно кадров: 8.
Соседи: Emily · Dungeon — закрыты.») → **одна** continuation-генерация с
уже НОВЫМ манифестом/витриной, затем жёсткий стоп (второй туре команды
исполняются, но петлю не ретриггерят — анти-loop по построению). Всё за
конфиг-флагом `agenticLoop: false` → полевой тест на 12b → решаем дефолт.
Цена удвоения оплачивается только на переходах, не на каждом туре.

**Плюсы-шлифовка B:**
- Tool-result компактный и детерминированный (генерим сами, не модель) —
  это FSM-observation: состояние + соседи-меню. Красиво ложится на тезис
  «таб = состояние, список свёрнутых = меню переходов».
- UX: индикатор «🎬 осматривается…» во второй генерации; в чат пишется
  одно сшитое assistant-сообщение (или два с меткой — решить при реализации).
- Стриминг-команды исполняются шиной как раньше — петля стартует ПОСЛЕ
  полного ответа и очереди команд (точка интеграции: граница тура в
  projector-session).

**C. Полная петля (все команды, глубина 2–3).** Максимум агентности: IMG,
FOCUS, FX тоже дают наблюдения; каскады самокоррекции. Цена: время ×2–3 на
многих турах, сложность анти-loop, чат пестрит служебными сообщениями.
По совести — рано: без полевых данных B это стрельба из пушки.

**D. Суррогат без петли: narration injection.** Tool-result сообщение в чат
СРАЗУ (без второго инференса): юзер видит «🎬 Модель вошла в Tavern (8
кадров)», модель информирована к следующему туру бесплатно. Не даёт
«описать сейчас», но стоит ноль и лечит половину боли FSM-глубины. Может
быть первым шагом или жить в паре с B (в ленте видно переход).

## 4. Открытые вопросы — РЕШЕНИЯ ВЛАДЕЛЬЦА (2026-07-29)

1. **Главный вопрос:** РЕШЕНО — **B, микро-петля dir-only, глубина 1**
   (реализовано в `24-agentic-micro-loop`).
2. Дефолт флага: **off**, включение чекбоксом «Agentic loop (scene
   transitions)» в настройках модели; полевой тест на 12b решает будущий
   дефолт.
3. Запись в чат: один сшитый assistant-ответ (обе генерации пишутся в одно
   сообщение подряд; статус «👁 осматривается…» во время continuation).
4. Стоимость-страж: пока НЕ нужен — триггер только на переходах, восторжен-
   ность «open→close→open» смягчает глубина 1 (каскадов нет по построению) и
   идемпотентность v17 (повторное исполнение через субтитры безвредно).

## 5. Полевой репорт по v24 → РЕШЕНИЯ ВЛАДЕЛЬЦА 2.0 (2026-07-29, v25)

**Репорт:** «получилась неправильная петля»: модель дописывает сообщение,
после конца стрима оно УДАЛЯЕТСЯ, и тогда модель отвечает заново. Не похоже
на наши обычные петли: тул вызвался → результат вернулся → модель, ВИДЯ
результат, продолжает ответ. Предложение: сделать тул и поместить в него
команды.

**Диагноз (разведка):**
- «Удаление» — баг стрим-аккумуляции: `readStreamingResponse` на каждой
  итерации while-петли заводил счётчик текста с нуля и перезаписывал
  `m.raw`. В обычном тул-лупе баг невидим (текст рядом с tool_calls обычно
  пуст), в v24 — стирал настоящую речь. Лечение: сидирование из
  существующего `raw`; side effects (playback commit, эхо в контекст,
  activity-bus) остаются локальными для итерации (`own`), чтобы ничего не
  задваивалось.
- «Модель отвечает с визуальным контекстом коллажа» — отчасти иллюзия:
  зрительный инжект делается ОДИН раз до петли. Модель в continuation видит
  тот же инжект; свежего коллажа у неё НЕТ (лишь текст-наблюдение с тегами;
  старый коллаж мог уже содержать ассеты помеченного таба).

**Решения владельца (дословно, сжато):**
1. «Весь смысл затеи: модель после вызова команды открытия таба делает
   паузу и получает от агента НОВЫЙ собранный системой коллаж, из которого
   сразу выбирает ассет. Если такого эффекта не будет — смысл теряется.»
2. «Текстовые модели уже уходят в прошлое — за них не цепляемся.»
3. Глубина: **общий toolLoopLimit** (модель может пройти несколько комнат
   за тур — это фича).

**Реализация (v25):**
- **Новый тул `scene_navigate`** (vp-core-tools.js): `entity: tab|pack`,
  `action: open|close`, `name` (строгие enum — рельсы для слабых моделей).
  Исполнение через директор-шину `[TAB:open:X]`/`[CAT:…]` — соло-свип и
  fuzzy-match v17 даром. Затем ЧЕСТНАЯ ПАУЗА: опрос
  `VP.gallery.getCollagePublicState()` до двух спокойных замеров подряд
  (бюджет 15с, при таймауте — последний доступный рендер с честной пометкой).
  Возврат: JSON-срез мира (matched/resolved/openScenes/closedScenes/
  focusScene{pack, framesVisible, tags}) + **attachments** со свежим
  коллажем (dataUrl) + анти-repeat заметка.
- **Контракт vision-вложений** (vp-tools.js баннер): любой тул может вернуть
  `{ attachments: [{kind:'image', dataUrl, caption, tag}] }`. Сессионный
  тул-луп (обе ветки: стрим и non-stream фолбэк) превращает их в отдельное
  user-role vision-сообщение — тот же проверенный формат, что коллаж и
  фокус-кроп в getContextMessages. В JSON тула модели и в сохраняемую
  историю base64 **не попадает** (только метаданные) — токены и стораж целы.
- **Философия «tags=actions, tools=perception»** получила санкционированное
  владельцем исключение: гибрид ACTION+PERCEPTION допустим, когда ценность —
  в ВОЗВРАЩАЕМОМ наблюдении. Строка-амендмент в баннерах vp-tools.js и
  vp-core-tools.js.
- **Текстовая v24-петля остаётся как есть** (флаг agenticLoop) — дорога для
  toolsMode off; новых вложений не получает (п.2 решений). Описание тула
  просит модель предпочитать тул текстовым командам; двойное исполнение при
  смешении безвредно (идемпотентность v17).
- **Фикс стирания** лечит и нативный тул-луп (там латентно терялась речь
  перед вызовом тула): пузырь аккумулирует `full`, `own`-текст идёт в
  playback/контекст.
- Границы: зрительный инжект по-прежнему раз на тур (v25 добавляет точечное
  vision-сообщение, не переинжект мира); close-переход вложений не несёт
  («в холле смотреть нечего»); pack-переход — без focusScene.

**Тесты:** smoke-scene-navigate-tool.js (41), smoke-session-loop.js (27) —
аккумуляция, локальность side effects, санитизация base64, vision-мост,
инвариантность обычной отправки. Весь пакет смоуков 15/15 зелёный.
