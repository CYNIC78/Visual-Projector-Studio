# Бэкенд-рантаймы и VRAM-оркестровка — дизайн
**СТАТУС: РАЗВЕДКА + ПЛАН, решение за владельцем (эпоха укрепления фундамента, 2026-07-29).**

## 1. Проблема (слова владельца)
Проект работает на LM Studio; llama.cpp не внедрён. Боль: перед запуском
студии ассетов (sd.cpp) приходится ВРУЧНУЮ выгружать текстовую модель из
VRAM. Запуск модели в llama.cpp — «квест с мешком аргументов», интерфейс
под него неясен. Это блокирует юзабельность студии на одной GPU.

## 2. Разведка нашего кода (факты)
- Сессия бэкенд-агностична: дефолт `endpoint: http://localhost:1234/v1/chat/completions`
  (projector-session.js:31), пресет-кнопка «LM Studio» в панели модели
  (session-panels ~1670). Говорим чистый OpenAI-compatible HTTP.
- Студия УЖЕ оркеструет внешний процесс: `runCLI` строит команду sd.cpp и
  гоняет её через `Neutralino.os.spawnProcess(cmd, {cwd})` с fallback на
  `execCommand` (projector-asset-studio ~1914–2211), есть стоп-кнопка,
  парсер CLI-токенов, решённый квотинг путей Windows.
  `engineMode: cli | server` — server пока заглушка.
- Neutralino 6.8 даёт полный набор: `os.spawnProcess / execCommand /
  getSpawnedProcesses / updateSpawnedProcess`, `computer.getMemoryInfo`,
  `filesystem.showOpenDialog` (файл-пикеры).
- Управления ЖИЗНЕННЫМ ЦИКЛОМ моделей LM Studio у нас НЕТ вообще —
  только endpoint-строка.

## 3. Разведка внешнего мира (июль 2026)
**LM Studio умеет автоматизацию моделей (нам её просто не дёргали):**
- `lms` CLI (идёт с LM Studio): `lms load <m> [--gpu][--ttl][--context-length]`,
  `lms unload --all`, `lms ps [--json]`, `lms ls`, `lms server start`, headless
  daemon (`lms daemon up`).
- JIT-загрузка: запрос к модели, которой нет в памяти → LM Studio грузит её
  сам. **Следствие: после `lms unload --all` перезагрузка текст-модели
  БЕСПЛАТНАЯ — она случится на первом же сообщении чата** (ценой паузы
  загрузки на том первом сообщении).
- TTL (автовыгрузка по простою, дефолт аппа 60 мин, per-request поле `ttl`)
  и Auto-Evict («держать только последнюю JIT-модель»), нативный REST для
  unload (`POST /api/v1/models/unload`, новые версии).
**llama.cpp:**
- `llama-server` — тот же OpenAI-compatible API (`:8080/v1/chat/completions`),
  т.е. наша сессия подключается БЕЗ правок движка (только endpoint).
- Зрение (важно для нашего коллажа!): `--mmproj <projector.gguf>` —
  мультимодальность через mtmd, image_url в chat-completions поддержан.
- Мешок аргументов подтверждён: `-m, --mmproj, -c/--ctx-size,
  -ngl/--n-gpu-layers, -fa, --jinja, --temp, --port, --host…`.
- `llama-swap` — лёгкий прокси: держит НЕСКОЛЬКО моделей в конфиге и
  переключает их по имени в запросе (гасит/поднимает llama-server
  процессы сам). НО: про VRAM под sd.cpp он не знает — нашу боль
  он НЕ снимает (разгружает LLM только ради другой LLM).

## 4. Три рантайм-стратегии
| | A. LM Studio-стюард | B. llama.cpp-рантайм | C. llama-swap |
|---|---|---|---|
| Снимает боль «ручной выгрузки» | ✅ (lms unload→studio, JIT вернёт) | ✅ (мы владеем процессом) | ❌ (только LLM↔LLM) |
| Зрение для коллажа | как настроено в LMS | ✅ через --mmproj | ✅ |
| Кода | мало (хуки + пара кнопок) | средне (панель + lifecycle) | мало (док + пресет endpoint) |
| Зависимость | lms CLI/версия LMS | бинарники llama.cpp | внешний прокси + YAML-конфиг |
| Квест для владельца | почти нет | малый (форма-пресет) | высокий (YAML) |

## 5. Рекомендуемая лестница (НЕ строить до решения владельца)
1. **A — «VRAM-дворецкий» студии (✅ РЕАЛИЗОВАНО в v29, ждёт домашнего теста):**
   тоггл в настройках студии «Освобождать VRAM перед генерацией» + поле
   пути к `lms.exe` (автопоиск в PATH). Перед `runCLI`: `lms unload --all`;
   после — ничего (JIT вернёт модель сам на первом сообщении; опциональный
   тоггл «перезагрузить модель сразу» → `lms load <имя> --ttl 600`).
   Деградация: нет lms → тост «выгрузи модель вручную», генерация
   не блокируется. Бонус: пилюля статуса `lms ps --json` в панели студии.
2. **B — панель llama.cpp-рантайма (после домашних тестов A):**
   llama-server как нанятый процесс по образцу студийного runCLI:
   форма-пресет (6 ручек, ниже), Start/Stop, поллинг `/health`, запись
   endpoint в modelConfig. VRAM-хореография становится НАШЕЙ:
   Stop текст-сервер → sd.cpp → Start текст-сервер.
3. **C — llama-swap: только документированный горизонт** (владелец —
   не кодер, YAML-конфиг противоречит нашему правилу «всё через UI»).

## 6. Ответ на «мешок аргументов» (если B)
Не маппить каждый флаг. **Курировать 6 ручек**, остальное прятать:
1) файл модели (файл-пикер), 2) mmproj-файл (опц. файл-пикер; пусто =
текстовая модель, заполнено = зрение), 3) контекст (число, дефолт 8192),
4) слои на GPU (число, дефолт «все»), 5) flash-attn (тоггл),
6) порт (дефолт 8080).
Под спойлером «Дополнительные аргументы» — свободное raw-поле (точно как
существующий paste-box sd.cpp в студии ~1475: паттерн уже доказан на
нашем потолке сложности). Пресеты = обычный JSON в настройках, список
моделей с запомненными ручками. CLI собирается шаблоном — мешок превращается
в одну строку, которую можно посмотреть и скопировать.

## 7. Риски вслепую (честно)
- Windows-квотинг путей с пробелами при сборке CLI — но уже РЕШЁН в
  студийном парсере токенов; переиспользуем.
- Отсутствие `lms` у пользователя → только тост, без блокировок.
- JIT-перезагрузка: первое сообщение после студии будет с паузой —
  показать честный статус «модель просыпается…» (у LM Studio это видно
  в ответе-задержке; у нас — тост по таймауту ожидания).
- `os.execCommand/spawnProcess` требуют разрешений в neutralino.config —
  для sd.cpp они уже выданы (студия работает), тот же канал.

## 8. РЕШЕНИЕ ВЛАДЕЛЬЦА (2026-07-29) — дворецкий первым, форма для llama.cpp
- **Порядок работ:** сначала **A (VRAM-дворецкий, lms)** — минимум кода,
  боль снимается сегодня; llama.cpp-панель (B) — следующим актом после
  домашних тестов; llama-swap остаётся горизонтом.
- **Стиль интерфейса B (выбран заранее):** форма из 6 курированных ручек +
  raw-поле под спойлером (паттерн sd.cpp paste-box).

**Реализовано в v29 (`js/projector-asset-studio.js`, всё opt-in, дефолт ВЫКЛ):**
- Кнопка **🧹** в тулбар студии → поповер настроек: тоггл «Выгружать модели
  перед генерацией (`lms unload --all`)», поле пути к lms.exe (пусто = PATH),
  опциональный тоггл «Вернуть модель после» + поле идентификатора
  (`lms load <m> --ttl 600`; нужно только при выключенном JIT) + JIT-подсказка.
- Хуки: `vramPreFlight` перед одиночной генерацией и ОДИН раз перед пакетом
  «▶▶ All»; `vramPostFlight` после (try/finally в обоих путях).
- Конфиг: `S.assetStudio.config.{vramSteward, lmsPath, stewardReload,
  stewardModel}` — персистится вместе со студией; кнопка 🧹 показывает
  состояние (яркая/приглушённая) и статус в тултипе.
- Мягкая деградация: нет Neutralino / нет lms / exit≠0 → строка в логе
  студии + тост «управляй моделью вручную»; генерация НИКОГДА не блокируется.
