# CURRENT_STATE — Текущее состояние проекта

> Обновлено: после аудита кода (все `.js` проходят `node --check`, `eval()` отсутствует).  
> Контекст: исследовательский проект, трастед-режим, разработчик — один человек + AI.  
> Документ не претендует на финальность; обновляется после каждого удачного или неудачного эксперимента.

## 1. Общая позиция

Проект движется **без чёткого плана**, заходя на неисследованную территорию. Мы работаем в режиме «эксперимент → укрепление фундамента → следующий эксперимент». Последний крупный рефакторинг — **модульность** (регистры панелей, провайдеров подсказок, командная шина `VPCommandBus`). Некоторые взаимосвязи мы **намеренно не перенесли** на работу через хаб (`VP_HUB`) — это решение сохраняет скорость разработки в одиночку.

## 3. Что является экспериментом (не укреплено полностью)

| Компонент | Статус | Что экспериментально | Риски / Примечания |
|---|---|---|---|
| **Asset Pack Factory (`projector-asset-studio.js`)** | Эксперимент | `configure_prompt_studio` — подготовка Prompt Nodes для batch-генерации. Правило v1: 1 Prompt Node = 1 сгенерированный ассет = 1 таб галереи. `Produce All` / `Apply All` — массовая генерация и применение драфтов. | Полная интеграция с моделью (`LLM` через `configure_prompt_studio`) остаётся в стадии доработки. | **Depth Renderer (`projector-depth-renderer.js`)** | Эксперимент / Работает | `updateProjectorDepthLayer()` — рендер 2.5D через WebGL (`VPDepthRenderer`). Поддерживает `inverted` карты глубины, `pivot`, `vignette`, `strengthMultiplier`. `performFocalLockAtClick()` — блокировка фокуса по клику. | Работает, но не полностью интегрирован в систему команд (`[FOCUS:...]` не включает/выключает глубину автоматически; это делается через UI или код). `depthMap.file` читается через `Neutralino.filesystem.readBinaryFile()` — если файл отсутствует или повреждён, ошибка обрабатывается (`catch`), но визуальный фидбек минимален. |
| **Модульная система (`PanelRegistry`, `PromptProviderRegistry`)** | Недавно укреплено | `registerPanel()`, `registerPromptProvider()`. Регистры используются для динамической сборки интерфейса и контекста подсказок (`buildPromptProviderContext()`). | Некоторые панели и провайдеры регистрируются напрямую в `visual-projector.js`, а не через `VP_HUB.registerModule()`. Это оставлено намеренно. |
| **Playback синхронизация (`Playback.sync`)** | Работает, но не через хаб в обязательном порядке | `Playback.sync(sessionMessages)` — перезаписывает `State.playback.messages` сообщениями сессии. Используется для синхронизации с `projector-session.js`. | Связь прямая (`visual-projector.js` ↔ `session`), не проходит через `hub.handle('playback:sync')` в обязательном порядке (хотя хаб регистрирует алиас). |
| **Focus Mode (`projectorViewport`)** | Работает стабильно | `setProjectorViewport()`, `panProjectorViewport()`, `toggleProjectorViewportZoom()`, `resetProjectorViewport()`. Автосохранение настроек viewport в метаданные текущего ассета (`State.current.focusViewport`). | `updateProjectorDepthLayer()` вызывается из `applyProjectorViewportUI()` — это прямая связь, не через хаб. Решение оставить как есть. |

**Focus Mode — «мягкий» 4:3 (сознательное решение, 2026-07-27):** экран в Focus Mode держит `width` = ширина панели и `max-height` как потолок по вертикали (`.vp-screen.vp-focus-mode` в `css/visual-projector.css` + инлайн-дублирование в `applyProjectorViewportUI()`, `visual-projector.js`). Когда панель широкая и невысокая, соотношение сторон уезжает шире 4:3 — CSS не может держать обе стороны жёстко одновременно через `aspect-ratio`, когда обе явно заданы. Разработчик подтвердил, что это устраивает как есть: экран всегда без пустых полей заполняет ширину панели, а пропорция плавает при экстремальных формах панели. Если позже понадобится **жёсткий** 4:3 (например, для стабильного маппинга координат мыши/клавиатуры на экране), нужно перейти на леттербоксинг — фиксированный 4:3 блок, отцентрированный, с пустым фоном по краям. См. комментарии прямо в коде рядом с обоими местами.

## 4. Что оставлено без переноса на хаб (`VP_HUB`)

Ниже перечислены связи, которые **намеренно не были перенесены** на обязательное прохождение через `window.VP_HUB`. Это решение принято для сохранения скорости разработки в режиме одного разработчика.

| Связь | Кто вызывает | Кого | Почему не через хаб |
|---|---|---|---|
| Обновление галереи при смене кадра | `visual-projector.js` (`updateProjectorUI`) | `window.VisualProjector?.gallery?.refreshGalleryPanelUI()` | Прямая связь для немедленной реакции UI на смену `State.current`. Перенос на `hub.emit('gallery:refresh')` добавил бы задержку и сложность без явной выгоды в одиночном режиме. |
| Сохранение viewport в RAM | `visual-projector.js` (`setProjectorViewport`) | `window.VisualProjector?.gallery?.persistAsset()` | Сохранение настроек камеры (`focusViewport`) в метаданные ассета. Прямая связь для скорости; хаб используется для внешних запросов (`projector:get-viewport`). |
| Добавление изображения из файла (drop) | `visual-projector.js` (`setupDragAndDrop`) | `window.VisualProjector?.gallery?.addImageFromBlob()` | UI-уровень; прямая передача файла в галерею без промежуточного события хаба. |
| Прикрепление снимка фокуса к сообщению | `visual-projector.js` (`captureBtn` click) | `window.VisualProjector?.session?.queueManifest()` | Немедленная реакция на действие пользователя (нажатие кнопки «Snapshot Focus»). Прямая связь сохраняет отзывчивость. |
| `Playback.sync()` | `visual-projector.js` (`Playback.sync`) | Не через хаб в обязательном порядке (хаб имеет `playback:sync` как алиас) | Внутренний поток управления историей воспроизведения остаётся прямым; `hub.handle()` зарегистрирован для внешнего доступа. |
| `setCurrent()` | `visual-projector.js` | Не через `hub.handle('projector:set-current')` в обязательном порядке (хаб имеет алиас) | Критический путь смены кадра должен быть мгновенным; хаб используется для удалённых команд. |

## 5. Экспериментальные заметки (дневник)

### 5.1 Удачные эксперименты

- **Командная шина (`VPCommandBus`)**: замена разрозненных вызовов на единый реестр с нормализацией и логированием значительно упростила добавление новых команд (`FOCUS`, `ACTIVITY_*`).
- **Модульные регистры (`PanelRegistry`, `PromptProviderRegistry`)**: позволили разделить логику UI и контекста подсказок без изменения ядра.
- **Драфты в галерее**: система `_draft` + `Apply` защитила `data/worlds/` от случайного «мусора» при генерации ассетов.
- **Защита FX (`try/catch` в `fire()`)**: позволила загружать сторонние `.js` FX Pack в трастед-режиме без риска падения всего приложения.
- **Манифест с динамическим инъектом (`[CAMERA CONTROLS]`)**: автоматическая вставка инструкций камеры при включённом `Focus Mode` улучшила взаимодействие с моделью.

### 5.2 Неудачные или незавершённые пробы

- **Полный перенос всех связей на `VP_HUB`**: попытка сделать `setCurrent()`, `Playback.sync()` и обновление галереи обязательными через хаб привела к избыточной сложности и потенциальным задержкам в отклике. Решение — оставить прямые связи для критических путей, хаб — для внешних интерфейсов.
- **Миграция `docs/`**: папка `docs/` существует локально на компьютере разработчика, но содержит десятки файлов от разных версий (до и после рефакторингов). Попытка синхронизировать её с репозиторием привела бы к путанице. Решение — создавать минимальный набор актуальных документов (`PROJECT_MAP.md`, `CURRENT_STATE.md`) отдельно от локального архива.
- **Автоматизированное тестирование (`package.json`, `vitest`)**: попытка внедрения фреймворка тестирования отложена, так как весь код написан AI по идеям разработчика, и разработчик не работает с кодом напрямую; ручная проверка (`node --check`) и визуальная проверка через `Neutralino` остаются основными методами контроля.

## 7. Примечания о коде и разработке

- **Весь код в `js/` написан AI-ассистентом** по идеям разработчика (совместные сессии брейншторма). Разработчик не читает код напрямую, но понимает архитектуру через объяснения AI и визуальную проверку работы приложения.
- **Нет `package.json` или системы управления зависимостями**: единственный `vendor` — `jszip.min.js`; `neutralino-win_x64.exe` жёстко привязан к `6.8.0`. Обновления бинарников требуют ручной замены.
- **Нет `.github/workflows/` или CI/CD**: сборка лаунчера (`launcher/build-launcher.bat`) предполагает наличие `Visual Studio 2022 Build Tools`; релиз `VP Studio.exe` делается вручную.
- **Бинарники в репозитории** (`VP Studio.exe`, `neutralino-win_x64.exe`, `.dll`, `.obj`) увеличивают размер `git clone`; они не должны быть в `main` для коммерческого релиза, но для исследовательского проекта это приемлемо (быстрый запуск без сборки).
- **Документация `docs/` существует локально**, но содержит архивы разных версий. Этот файл (`CURRENT_STATE.md`) — актуальный срез состояния после последнего аудита и рефакторинга.
